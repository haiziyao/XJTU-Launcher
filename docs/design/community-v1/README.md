# 社区广场 v1 规划（2026-11-10，默认导航页已实现，待真机验收）

社区广场是**随应用分发的只读校园内容库**：社团、课程攻略、校园生活、生涯分享和资源导航。内容先随安装包离线可用，之后通过 OSS 下发内容包更新，不依赖发版。

**当前范围（2026-11-10 用户确认）**：v1 先只做默认导航页、中下部分的全局搜索框、普通 / Agent 模式切换，以及 Agent 设置里的搜索服务开关；点进任何一个板块都只显示「待开发」，真正的板块页、详情页和内容包后续再做。

本文件同时确定后续内容格式和更新方式。默认导航页已按用户 2026-11-10 的指示实现；参考图见 [reference-default.svg](reference-default.svg)，视觉与交互仍待用户真机验收，未验收前不对外宣称「社区广场已上线」。

## 1. 定位与边界

- 面向西交学生的策展内容，不是论坛。v1 没有账号、发帖、评论、点赞、投稿、私信或用户主页。
- 内容与应用版本解耦：应用只提供阅读器，内容以数据包形式更新；更新内容不需要重新安装应用。
- 离线优先：安装包自带一份完整内容；下载过新内容包后也保存在本机，断网仍可阅读。
- 与插件中心的「校园广场」不是同一个东西。后者是内置插件的分类名；社区广场是独立的一级页面，不参与插件启停。
- 与应用内其他区域分工：
  - 「畅行校园 → 课程资料」和「工作台」放用户自己的课程附件与作业文件，社区不碰这些文件。
  - 社区只做公开的、可署名的介绍与经验，不读取校园账号、课表、成绩或任何个人数据。
- 不采用 P2P、用户互传或远端插件。2026-10-31 已评估并搁置社区 P2P；本方案仍然只做单向、可审核的静态内容分发。

## 2. v1 不做

- 不内嵌网页、不执行内容包里的 HTML / JavaScript，不提供任意 URL 的 WebView。
- 不做课程资料、往年题、教材 PDF 等版权风险内容；需要时只链到权利方页面。
- 不做教师打分 / 评价。课程板块只放课程号、课程名、学习建议与选课经验；涉及具体教师的负面或未经证实的说法不进入内容包。
- 不做用户投稿入口。后续贡献走「GitHub PR / 表单 → 人工审核 → 生成新内容包」，审核和账号体系齐备后再考虑应用内投稿。
- 不做社区同步、云收藏、阅读记录上传。阅读偏好如以后要做，只存本机。

## 3. 信息架构

侧栏一级入口从「社区」改为「社区广场」，位置不动（主页 / Agent / 社区广场 / 畅行校园 / 工作台）。

五个固定板块：

| id        | 名称     | 内容                               | 典型条目                           |
| --------- | -------- | ---------------------------------- | ---------------------------------- |
| `clubs`   | 社团     | 社团介绍、活动、招新信息           | 社团档案、招新时间、官方公众号文章 |
| `courses` | 课程攻略 | 课程号、课程名、学习建议、选课经验 | 某门课怎么学、先修关系、考核形式   |
| `life`    | 校园生活 | 吃住行、办事流程、校园设施         | 食堂、校医院、快递、场馆、办事指南 |
| `career`  | 生涯分享 | 升学、就业、竞赛、科研与成长经验   | 保研 / 考研 / 出国 / 实习经验      |
| `links`   | 资源导航 | 官方与第三方资源站引用             | 教务处、图书馆、正版软件、开源工具 |

板块 id 固定，内容包不能新增板块。新增板块属于产品决定，需要随应用版本更新图标、名称和文案。

### 页面结构（v1 只实现默认导航页）

**默认导航页**是 v1 唯一实现的页面，只负责导航：

- 顶部只有页面标题，不放假内容、精选、最近更新或统计。
- 主体是五个**矩形格子**，一行三个，五个板块自然排成 3 + 2。
- 每个格子里左边是板块标题和一句范围说明，右边是图片区；图片以淡入淡出方式切换，不铺满整张卡片。
- 图片默认自动交叉淡入淡出；悬停、键盘聚焦和 `prefers-reduced-motion` 下停止自动切换，只显示当前图。没有图片时用板块图标和中性底色占位，不伪造图片。
- 中下部分放一个全局搜索框，默认页顶部不放搜索框。
- 点击板块卡进入板块页。**v1 板块页只显示「待开发」占位**，不展示假的列表或详情。

```text
┌────────────────────────┐ ┌────────────────────────┐ ┌────────────────────────┐
│ 社团            [图片] │ │ 课程攻略        [图片] │ │ 校园生活        [图片] │
│ 介绍 / 活动 / 招新      │ │ 课程号 / 学习建议      │ │ 吃住行 / 办事指南      │
└────────────────────────┘ └────────────────────────┘ └────────────────────────┘
┌────────────────────────┐ ┌────────────────────────┐
│ 生涯分享        [图片] │ │ 资源导航        [图片] │
│ 升学 / 就业 / 成长      │ │ 官方 / 第三方资源站    │
└────────────────────────┘ └────────────────────────┘

              ┌──────────────────────────────────────────────┐
              │ 搜索社区…                            🔍  普通 │
              └──────────────────────────────────────────────┘
```

**板块页 / 详情页（后续实现，当前只到「待开发」）**：

- 点击板块后才进入该板块的真正页面；板块页有自己的搜索框，和默认页的全局搜索框不是同一个。
- 后续板块页包含板块说明、关键词搜索、标签筛选和内容列表；不同类别的资源通过分栏和分隔线区分。
- 课程板块的搜索必须支持课程号；课程卡先显示课程号，再显示课程名。
- 详情页包含返回、封面、标题、摘要、信息卡（`facts`）、正文、相关链接、来源与授权、更新时间和过期提示。
- v1 点进任何板块都只显示「该板块正在开发」和返回按钮，不出现示例条目。

### 全局搜索框与 Agent 模式

- 位置：默认导航页中下部分，水平居中；窄窗口下左右留边、不贴边。
- 组成：输入框、🔍 和紧挨着 🔍 的模式切换按钮。按钮显示当前模式「普通」或「Agent」，点击切换。
- 默认模式：普通。
- **普通搜索**：本地搜索，不依赖 Agent。v1 只有板块导航索引，匹配板块名称和说明；没有板块内容时明确显示「内容待开发」，不伪造结果。后续接入内容包后，再扩展为标题、摘要、标签、课程号和正文搜索。
- **Agent 搜索**：复用现有 Agent 运行时，把查询和公开的社区导航 / 内容索引交给模型，返回回答并标明引用；没有可引用的社区内容时，明确标注「Agent 回答，未引用社区内容」，不说自己搜索过不存在的条目。
- 模式切换只在点击或键盘操作时触发，不在页面加载时自动请求模型。

#### Agent 搜索可用性

按顺序检查，任何一项不满足都禁用 Agent 模式，并在按钮的 tooltip / 状态文字里说明原因：

1. `cn.xjtu.agent-settings` 插件处于启用状态；插件被关闭时提示「Agent 未启用」。
2. Agent 设置里的「开启搜索服务 Agent」开关已打开；关闭时提示「未开启搜索服务 Agent」。
3. 已配置默认模型服务；没有时提示「未配置模型服务」。
4. 模型服务可达；不可达时提示「模型服务不可达」。

补充约定：

- `agentSidebarVisible` 只控制侧栏入口是否显示，不单独决定 Agent 搜索可用性；隐藏侧栏但插件和模型正常时，搜索仍可用。
- 可达性在用户第一次切到 Agent 模式或提交 Agent 搜索时检查，设置 3–5 秒超时，结果缓存约 60 秒；不在后台轮询，不在打开页面时自动请求模型。
- Agent 搜索失败或超时后，提示原因并切回普通搜索；结果不明不自动重试。
- Agent 搜索只发送查询文本和公开社区索引，不发送校园凭据、Cookie、课表、成绩、本机路径或用户文件。
- 检索真正接入内容包后，Agent 回答必须列出引用的社区条目；没有引用时不能把模型生成的内容说成社区内容。

#### Agent 设置开关

- 在「Agent 设置 → 基础设置」第一页新增一行「搜索服务」，开关标题「开启搜索服务 Agent」，默认关闭。
- 配置字段 `agentSearchEnabled: boolean`，写入 `config.json`，后端缺省为 `false`；旧配置升级后保持关闭，不擅自开启。
- 按设置页现有行式结构，只加标题和开关，不加解释小字；不可用原因放在社区搜索框的 tooltip 里。

### 交互约定

- 详情页是社区页内部视图，不新增侧栏入口；`Esc` 和返回按钮回到上一级并恢复滚动位置。
- 正文里的 HTTP / HTTPS 链接交给系统浏览器打开，不在应用内导航；站内锚点留在当前页。
- 外部链接卡显示域名和「外部链接」标记，不自动抓取页面、不内嵌、不预加载。
- 内容包只提供图片和数据，不提供样式；字体、颜色、间距全部沿用应用现有设计系统。
- 内容卡不伪造图片：没有封面时用板块图标和中性底色占位。
- 默认页的搜索框只在中下部分；进入板块后才会出现板块内搜索框，两者不重复占位。

## 4. 内容包格式

一个内容包就是一个 JSON 文件，内置包和下载包使用同一格式。图片在构建时转成 `data:image/...;base64` 内嵌，避免额外资源协议、路径穿越和远程图片追踪。

```json
{
  "schemaVersion": 1,
  "revision": 1,
  "contentVersion": "2026.11.0",
  "updatedAt": "2026-11-10",
  "sections": [
    { "id": "clubs", "name": "社团", "description": "社团介绍、活动与招新", "icon": "users" },
    {
      "id": "courses",
      "name": "课程攻略",
      "description": "课程学习与选课经验",
      "icon": "book-open"
    },
    { "id": "life", "name": "校园生活", "description": "吃住行与办事指南", "icon": "map-pin" },
    {
      "id": "career",
      "name": "生涯分享",
      "description": "升学、就业与成长经验",
      "icon": "compass"
    },
    { "id": "links", "name": "资源导航", "description": "官方与第三方资源站", "icon": "link" }
  ],
  "items": [
    {
      "id": "clubs/example-club",
      "section": "clubs",
      "kind": "article",
      "title": "社团名称",
      "summary": "一句话说明这个社团做什么、适合谁。",
      "tags": ["机器人", "竞赛"],
      "cover": "data:image/webp;base64,...",
      "coverCredit": "图片：社团官方，已获授权",
      "facts": [
        { "label": "活动时间", "value": "每周三 19:00" },
        { "label": "招新", "value": "每年 9 月" }
      ],
      "links": [
        {
          "title": "官方公众号文章",
          "url": "https://example.xjtu.edu.cn/...",
          "description": "社团介绍与往期活动"
        }
      ],
      "source": {
        "name": "社团官方公众号",
        "url": "https://example.xjtu.edu.cn/...",
        "permission": "authorized"
      },
      "publishedAt": "2026-09-01",
      "updatedAt": "2026-10-20",
      "validUntil": "2027-06-30",
      "pinned": false,
      "body": "## 关于社团\n\n正文使用 Markdown。"
    },
    {
      "id": "courses/comp45010502",
      "section": "courses",
      "kind": "article",
      "title": "计算机网络原理",
      "summary": "课程号、先修关系、考核形式与学习建议。",
      "tags": ["专业必修", "网络"],
      "course": {
        "code": "COMP45010502",
        "name": "计算机网络原理",
        "credits": 3,
        "semester": "2026-2027 秋季学期"
      },
      "source": {
        "name": "课程攻略作者",
        "url": "https://example.xjtu.edu.cn/...",
        "permission": "authorized"
      },
      "updatedAt": "2026-10-20",
      "pinned": false,
      "body": "## 怎么学\n\n正文使用 Markdown。"
    }
  ]
}
```

### 字段约束

- `schemaVersion`：固定 `1`；应用只认这个版本。
- `revision`：内容修订号，整数，单调递增。应用只比较 `revision`，不拿日期判断新旧。
- `contentVersion`：给人看的版本，如 `2026.11.0`。
- `sections`：必须正好是上表五个 id，顺序固定；`icon` 只能取应用认识的图标名。
- `items`：最多 500 条；`id` 形如 `<section>/<slug>`，slug 为 `[a-z0-9][a-z0-9-]{0,63}`，跨修订号不得复用给不同内容。
- `kind`：`article`（正文必填）或 `link`（`links` 至少一条，正文可选）。
- `title` 1–60 字，`summary` 1–200 字，`tags` 最多 8 个、每个最多 16 字。
- `course`：只用于 `courses`。`code` 必填，4–24 位字母、数字或 `-`；`name` 必填 1–80 字；`credits` 可选 0–20；`semester` 可选，最多 40 字。其他板块不得出现 `course`。
- `facts`：最多 8 组，`label` 最多 12 字，`value` 最多 60 字。
- `links`：最多 12 条；只允许不含账号密码的 HTTP / HTTPS 地址；`title` 最多 60 字，`description` 最多 200 字。
- `source` 必填：`name`、`url`、`permission`。`permission` 取值：
  - `original`：项目自己撰写；
  - `authorized`：已获得作者 / 社团明确授权；
  - `official-public`：来自官方公开页面，已注明出处；
  - `link-only`：只引用外部链接，不复述正文。
- `publishedAt` / `updatedAt` 为 `YYYY-MM-DD`；`updatedAt` 必填。`validUntil` 可选，用于招新、活动等时效信息；过期后显示「已过期」并排在后面，但不自动删除。
- `body` 最多 40,000 字；只允许 Markdown，不允许 HTML、远程图片、`javascript:` 链接和表单控件。
- **体积硬约束（2026-11-10 用户确认）**：
  - 整个模块的**内容**（JSON 文本 + Markdown 正文，不含图片）合计不超过 **10 MB**；
  - 单条内容的**内容**不超过 **2 MB**；
  - 图片资源不计入上述 10 MB / 2 MB，但仍要压缩：建议单张 ≤300 KiB、单条 ≤8 张；
  - 超过 10 MB / 2 MB 的内容不默认放入安装包，放 OSS；内置包只保留未超限内容；
  - 如果图片让内置包明显变大，也按同一原则转 OSS，不默认打进安装包；
  - v1 先只发符合限额的内置包，远端大资源和内容包更新等 HTTPS 可用后再接。
- 渲染前再次用 `marked` + `DOMPurify` 清洗；正文图片只允许 `data:image/(png|jpeg|webp|avif|gif);base64,`。现有 `src/shared/markdown.ts` 的清洗规则需要为本页单独放宽 `img`，并保留其余限制。

### 搜索与过期

- 搜索文本由前端从 `title`、`summary`、`tags`、`course.code`、`course.name` 和正文纯文本生成，不单独存字段。
- 课程号完全一致排最前；其次课程号前缀匹配；再是课程名、标题、摘要、标签与正文匹配。匹配不区分大小写，忽略空格。
- `updatedAt` 超过 12 个月的内容显示「信息可能已过期」；`validUntil` 已过的内容显示「已过期」。两者都只是提示，不隐藏内容。
- 板块页默认按置顶、`updatedAt` 倒序；过期内容排在最后。

## 5. 内容生产与构建

源内容放在仓库根目录 `community/`：

```text
community/
├─ README.md                 # 作者与审核说明
├─ sections.json             # 五个板块的固定元数据
├─ items/
│  ├─ clubs/<slug>.md        # YAML frontmatter + Markdown 正文
│  ├─ courses/<slug>.md
│  ├─ life/<slug>.md
│  ├─ career/<slug>.md
│  └─ links/<slug>.md
├─ assets/<section>/<slug>/  # WebP / JPEG / PNG，构建时内嵌
└─ pack.json                 # 生成并提交，供 Rust include_str! 使用
```

- 每篇条目一个 Markdown 文件，frontmatter 写 `title`、`summary`、`tags`、`cover`、`facts`、`links`、`source`、日期等字段，正文写 Markdown；课程条目额外写 `course.code` / `course.name`。
- `scripts/build-community.mjs` 读取源文件，校验字段与图片，内联图片，生成 `community/pack.json`。Rust 用 `include_str!("../../community/pack.json")` 把内置包编进二进制。
- 构建脚本分别统计「非图片内容」的总量和单条大小：总量超过 10 MB 或单条超过 2 MB 时失败，并列出需要转 OSS 的条目；图片不计入这两个数字，但会提示内置包的总体积。
- 构建脚本失败必须让 `npm run build` 失败，不能带着坏内容发版。
- 运行时 Rust 对下载包重新执行同一套校验；不能只信构建脚本。
- 内容源文件与生成包都提交到仓库。生成包的内容变化要单独 review，不能只看源码 diff。
- 新增 `gray-matter`（只用于构建）等依赖时按项目约定精确锁定版本；若不想加依赖，用「JSON 元数据 + 单独 .md 正文」也可以，但不要手写脆弱的 YAML 解析器。

### 首批内容的硬要求

**不伪造内容。** 首批内容后续由用户提供；在拿到真实内容、来源和授权方式之前，不生成社团、课程、生活或生涯条目。v1 只做导航占位，构建流程、阅读器和板块页放到第二阶段。示例 JSON 只用于说明格式，不能作为发布内容。

收到内容后：

1. 先核对来源与授权，再写入 `community/`；
2. 能放进 10 MB / 2 MB 限额的随安装包发布；
3. 超过限额的条目标记出来，后续放 OSS，不默认进安装包；
4. 课程板块只收录课程号、课程名、学习建议和选课经验；不收录未经证实的教师评价、往年题和教材扫描件；
5. 生涯分享标注「个人经验，不代表学校」；个人经验需作者同意，可匿名。

## 6. 应用实现

### v1（只做默认导航页）

- 前端改造 `CommunityView.vue`：
  - 默认导航页：页面标题、五个矩形板块卡（3 + 2）、中下部分全局搜索框、模式切换按钮；
  - 点击板块卡进入板块占位页，只显示「该板块正在开发」和返回；
  - 不实现板块列表、详情页、内容包读取和内容搜索；普通搜索 v1 只匹配五个板块的名称和说明；
  - 侧栏名称改为「社区广场」。
- 新增配置字段 `agentSearchEnabled: boolean`，默认 `false`：
  - `src/types/index.ts`、`src/shared/domain.ts` 补字段；
  - `src-tauri/src/core/config.rs` 用 `#[serde(default)]` 兼容旧配置，默认关闭；
  - Agent 设置「基础设置」第一页新增「搜索服务」开关，只加标题和开关，不加解释小字。
- 新增 Agent 搜索可用性检查：
  - 后端提供 `agent_search_status()`，依次检查 `cn.xjtu.agent-settings` 是否启用、`agentSearchEnabled` 是否为真、是否配置默认模型服务；
  - 用户切到 Agent 模式或提交 Agent 搜索时再做可达性检查，3–5 秒超时，结果缓存约 60 秒；不在打开页面时自动请求模型；
  - 返回 `available`、`reason`（`plugin-disabled` / `disabled` / `no-model` / `unreachable` / `ready`）和可选的模型服务名称。
- v1 的 Agent 搜索复用现有 Agent / 模型服务调用路径，返回文本回答；没有社区内容可引用时明确标注「Agent 回答，未引用社区内容」。不新建持久对话，不写入 Agent 历史。
- 社区页不获得任何校园凭据、课表或成绩接口权限；只调用 `open_external` 打开链接。

### 第二阶段（板块内容接入后）

- 新增 `src-tauri/src/features/community.rs`：
  - `community_pack()`：返回当前生效的内容包（下载包优先，否则内置包），附来源、修订号和内容版本；
  - `community_check_update()` / `community_install_update()`：OSS 更新使用，返回检查、下载、校验、安装状态；
  - 包校验：字段、数量、URL、课程号、图片 MIME、base64 大小、ID 唯一性、板块合法性、修订号和 10 MB / 2 MB 限额；
  - 下载包损坏时回退内置包，保留错误信息供页面提示，不删除用户文件。
- 板块页、详情页和内容搜索按第 3 节实现；课程号搜索排序同时接入。
- 下载包位置：`~/.xjtu-launcher/resources/community/pack.json`；检查状态放 `~/.xjtu-launcher/state/community.json`。社区内容与账号无关，不做账号隔离，也不参与存储迁移。
- 内容包读取使用原子替换（临时文件 → 校验 → rename），保留上一份 `pack.json.bak` 以便回滚。
- 图片用内嵌 data URI；非图片内容按 10 MB / 2 MB 限额校验。图片让内置包过大时，同样转 OSS，不默认进安装包；不引入「zip + 本地资源协议」。

## 7. OSS 更新流程（第二阶段）

- 更新清单：
  `https://<域名>/community/latest.json`
  ```json
  {
    "schemaVersion": 1,
    "revision": 8,
    "contentVersion": "2026.12.0",
    "minAppVersion": "0.7.0",
    "url": "https://<域名>/community/packs/pack-8.json",
    "sha256": "<64 位十六进制>",
    "size": 3456789,
    "signature": "<minisign 签名，可选但推荐>"
  }
  ```
- **只在 HTTPS 可用后启用远端更新。** 内容包虽然不含隐私，但 HTTP 下清单和包可被替换；不能用「和软件更新一样先走 HTTP」作为理由扩大攻击面。P0 完成前，社区只用内置包。
- 超过 10 MB / 2 MB 的内容和大资源只放 OSS，不嵌入安装包；内置包只保留索引、正文和合规图片。需要下载的大资源用外部链接或后续资源字段引用，不在安装包里放副本。
- 下载后校验 `size` 和 SHA-256，再解析并执行完整校验；签名使用独立于应用更新密钥的内容签名密钥，公钥编进应用。清单里的 `minAppVersion` 高于当前版本时忽略该包，提示先更新应用。
- 检查策略：打开社区页时最多每 24 小时静默检查一次；有更新时显示「有新内容」提示，用户点击后再下载，不自动消耗流量。手动「检查内容更新」不受 24 小时限制。
- 安装失败保持旧包；下载中断不留下半包；结果不明不自动重试。
- 发布流程：内容合并 → 构建 `pack.json` → 上传 OSS → 更新 `latest.json` → 验证旧版本应用能回退。`latest.json` 与包都保留上一版，便于回滚。
- 官网 `/community/` 之后可以直接从同一份 `pack.json` 生成静态页面，和应用共用内容源；这是第三阶段，不在 v1 内。

## 8. 内容治理

- 每条内容必须有来源和授权方式；没有来源的「听说」「网传」不收录。
- 不写学生姓名、电话、学号、宿舍门牌、个人社交账号；社团联系方式只用官方公开渠道。
- 不使用未经授权的社团 Logo、活动照片、教材、课件、往年题；图片单独记录 `coverCredit`。
- 外部资源只做链接引用，不镜像、不绕过付费墙、不抓取需要登录的页面。
- 每个学期复核社团与生活信息，每年复核生涯内容；过期内容加提示，不装作仍然有效。
- 提供纠错渠道（GitHub Issue 或官网联系方式），收到更正后在新修订号中删除或修改；旧缓存包在下一次更新前仍可能显示旧内容，这是离线优先的已知限制。
- 内容包是公开数据，不包含任何校园账号信息、Cookie、API Key 或本机路径。

## 10. 验收口径

- **代码实现**：v1 默认导航页、全局搜索框、模式切换、Agent 可用性检查和 Agent 设置开关已完成；板块页只有待开发占位。
- **自动测试**：前端覆盖普通搜索匹配板块、关键词与空结果、Agent 不可用文案；后端覆盖配置默认关闭与旧配置兼容、三种模型协议的非流式回答解析。Agent 可用性矩阵的完整集成测试仍需真实模型配置后补；第二阶段再覆盖内容包校验、10 MB / 2 MB 限额、下载包优先级、损坏回退、课程号搜索排序、通用搜索与过期排序、Markdown 清洗。
- **真实内容**：第二阶段至少一个板块有真实、已授权的内容；v1 不宣称已有社区内容。
- **真机验证**：macOS 打开社区默认页、普通搜索、Agent 模式可用与不可用状态、Agent 设置开关仍未由用户验收；Windows 未验证前不宣称支持。
- **用户验收**：视觉与内容由用户确认；未确认前不对外说「社区广场已上线」。

## 11. 已确认与待确认

2026-11-10 用户确认：

1. **板块名和入口**：社团 / 课程攻略 / 校园生活 / 生涯分享 / 资源导航；侧栏叫「社区广场」。
2. **默认页板块样式**：矩形格子，一行三个；左边标题，右边淡入淡出的图片；用分栏和分隔线区分不同类别的资源。
3. **边界**：v1 只读，无账号、评论、投稿、点赞、云同步。
4. **课程板块**：支持关键词搜索，并支持课程号匹配；课程号完全一致优先。
5. **内容来源**：首批及后续资源由用户提供；不自行收集或编造条目。
6. **体积硬约束**：整个模块非图片内容合计 ≤10 MB，单条非图片内容 ≤2 MB；图片不计入这两个数字；超过的放 OSS，不默认放入安装包。第一版按此执行。
7. **默认页**：只是一个导航页；点击具体板块后才进入真正的板块页；v1 板块页先显示「待开发」。
8. **全局搜索**：默认页中下部分放一个全局搜索框；搜索框 🔍 附近有普通 / Agent 模式切换按钮；Agent 不可用时禁用。进入板块后的板块内搜索框属于后续实现。
9. **Agent 可用性**：没有 Agent 插件、未开启搜索服务 Agent、未配置模型服务或模型服务不可达时，Agent 模式不可用；Agent 设置第一页新增「开启搜索服务 Agent」开关，默认关闭。

实现时已先按以下选择落地，均需在真机验收时确认：

- 图片区使用两组抽象色块与板块图标交叉淡入淡出，悬停 / 键盘聚焦暂停，每张板块卡只有一组视觉，不轮播多图；
- 普通搜索结果在搜索框下方展开面板，不进入单独结果页；
- Agent 搜索回答为纯文本，固定标注「Agent 回答，未引用社区内容」，不新建对话页；
- 板块页仍只有「该板块正在开发」，分栏数量等第二阶段实现时再定；
- 远端 OSS 下载继续等 HTTPS 可用后再开。
