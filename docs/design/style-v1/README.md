## 三层结构

1. **调色板**：背景、表面、三级文字、边框、强调色、类别色、状态色。作者只写约 14 个值，
   其余（hover / pressed / soft / wash / focus ring / 卡片阴影）由程序推导，和现在的
   `accentTokens()` 一样。
2. **排版**：页面标题、分区标题、卡片标题、两级标签、正文、附注共 6 档字号，配套字重与行高。
   中文不再用负字距（`-0.01em` 是拉丁字母的紧排技巧，对中文无效）。
3. **抬头**：没有底板（2026-11-08 否决），只有墨色策略：
   - `adaptive`（默认）：按壁纸亮度自动选深 / 浅字，见下节；
   - `light` / `dark`：用户强制指定，供纯色壁纸或特殊偏好使用。

`chrome: band | flat | panel` 三个方案已作废。

## 与壁纸的关系（2026-11-08 改）

壁纸是底线：整个界面（含顶部）都必须是壁纸的背景，不用底板、不用整片蒙版。
抬头区因此没有任何填充，文字颜色必须自己适应壁纸。

做法：**自适应墨色**。

- 把壁纸缩到 64×64 画进离屏 canvas，按元素所在矩形取最暗 / 最亮像素的亮度。
- 分别算近黑 ink 与近白 ink 的对比度，取更高的那个；都不够 4.5:1 时退到纯黑 / 纯白。
- 任意纯色背景上，纯黑或纯白至少有一方 ≥4.5:1（最差点在 18% 亮度，正好 4.5），
  所以这条规则对任何单色区域都能成立；花壁纸按区域最坏像素判断。
- 只有两边都不达标（局部明暗跨度极大）时，才在那段文字后面加 ≤15% 的局部蒙版，
  不是整条横带。
- 重算时机：换壁纸、改清晰 / 均衡 / 透亮、窗口缩放、切换页面。

`scheme: light | dark` 只决定面板 / 卡片的底色，与抬头墨色解耦——卡片在深色壁纸下仍是
浅色半透明，壁纸透过卡片可见。

旧的 `wallpaperTokens()` 假设文字都落在浅色面板上，按「面板合成色」把 secondary / tertiary
往深里推，贴壁纸的文字必然掉；新规则不再改动文字去迁就面板。

## style.json

位置：`~/.xjtu-launcher/style.json`（与 `config.json` 同级；需要在约定手册里补一行）。
模型照 Ghostty：内置模板随应用发布，文件只存「选了哪套 + 用户改了什么」，避免应用更新
覆盖用户的自定义。

```json
{
  "version": 1,
  "preset": "paper",
  "overrides": {
    "palette": {
      "accent": "#c93a6b",
      "categories": { "academic": "#7a5af8" }
    },
    "typography": { "pageTitle": 26 },
    "ink": "adaptive"
  }
}
```

- `preset`：内置模板 id，缺失或未知时回退 `paper`。
- `overrides`：只写要改的值，其余继承模板。`preset: "custom"` 时必须给出完整调色板。
- 校验：颜色只接受 `#rrggbb`；字号 12–32；`ink` / `scheme` 是封闭枚举；未知字段忽略。
  不接受 `url()`、CSS 变量以外的字符串，避免把用户文件当成样式表执行。
- 旧的 `config.accent` 在首次启动时迁入 `overrides.palette.accent`，之后以 `style.json` 为准。

内置模板（建议先做三套）：

| id      | 名称 | scheme | ink      | 强调色   | 类别色（待办 / 通知 / 学习 / 学业 / 生活）        |
| ------- | ---- | ------ | ------ | -------- | ------------------------------------------------- |
| `paper` | 纸白 | light  | adaptive | `#1f6fe5` | 蓝 / 琥珀 / 蓝 / 紫罗兰 / 青碧                    |
| `ink`   | 墨黑 | dark   | adaptive | `#5b9dff` | 蓝 / 琥珀 / 蓝 / 紫罗兰 / 青碧（按深色底重新取值） |
| `warm`  | 暖纸 | light  | adaptive | `#a15c00` | 待定                                              |

## 风险与未决

- **深色模板成本最高**：现有样式里有约 120 个写死的颜色（课程表配色、插件图标、校园各页），
  需要逐项归入类别色或状态色，否则深色下必然出现浅底白字或深底黑字。
- 类别色要逐个校验对比度；`accent` 由用户改色后仍要满足 4.5:1。
- 壁纸 × 风格组合需要逐档验收（清晰 / 均衡 / 透亮）。
- 第三方自定义模板本轮不做，只支持内置模板 + overrides。
- Windows / WebView2 未验证。
