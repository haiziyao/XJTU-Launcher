## P0-1 更新镜像暂时使用 HTTP

- 状态：临时方案，待域名与证书就绪后切回 HTTPS。
- 决定日期：2026-10-25，决定人：用户。
- 服务器：`8.152.100.169`（阿里云，北京），由 nginx 直接提供静态文件。
- 内置更新地址：`http://8.152.100.169/xjtu-launcher/latest.json`。

### 原因

更新镜像目前没有可用域名，也还没有为 IP 地址申请证书，因此暂时用 HTTP 直连 IP。地址写死在发布配置和客户端兜底常量里，普通用户不需要填写更新源，也不会在界面上看到额外提示。

### 风险

- 更新清单 `latest.json` 在传输中可能被篡改。攻击者可以伪造版本号、说明或下载地址，造成降级、反复提示更新或拒绝服务。
- 安装包本身仍由 Tauri Updater 用编译进客户端的 minisign 公钥验证。清单被篡改不能直接影响签名校验，但可以引导客户端去下载旧版或无效文件。
- HTTP 不提供保密性；清单和安装包本身是公开内容，不涉及账号凭据。

### 代码位置

- `src-tauri/src/updates.rs`：`DEFAULT_ENDPOINT` 兜底地址；允许 `http` / `https`，仍拒绝账号密码和非 HTTP(S) 协议。
- `src-tauri/src/config.rs`：`bad_update_endpoint` 允许 `http` / `https`；配置校验测试覆盖临时 HTTP。
- `src/components/AppUpdateSettings.vue`：自定义镜像接受 HTTP(S)，界面不显示额外警告。
- `tools/prepare-release.mjs`：发布构建接受 HTTP 端点，构建日志打印 P0 提示。
- `.github/workflows/release.yml`：`XJTU_UPDATE_ENDPOINT` 写死为上述 HTTP 地址。

### 服务器配置

nginx 站点 `8.152.100.169_80.conf` 中新增：

```nginx
location ^~ /xjtu-launcher/ {
    alias /srv/xjtu-launcher/public/;
    autoindex off;
    add_header Cache-Control "no-cache";
}
```

文件放在 `/srv/xjtu-launcher/public/`：根目录放 `latest.json`，各版本安装包放在 `v<版本>/`。同一目录保留 `/.well-known/acme-challenge/`，供以后申请证书使用。
