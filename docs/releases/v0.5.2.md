# XJTU Launcher v0.5.2

发布日期：2026-10-30
状态：最新

## 摘要

修复 macOS 安装包提示“已损坏，无法打开”，撤回有同样问题的 0.5.1；校园工具按领域合并，Agent 与 MCP 的工具面从 33 个收敛到 14 个。

## 修复

- **macOS 打不开**：0.5.1 的 macOS 包只有二进制签名，应用包本身没有签名，Gatekeeper 判定损坏。0.5.2 起在发布时对应用包做 ad-hoc 签名，`codesign --verify --deep --strict` 可通过。
- **WebVPN 登录误判**：部分账号在 WebVPN 登录完成后会被带到映射后的校园站点，旧逻辑只接受回到门户首页，因而报“未收到预期的校园认证页面”。现在按地址、HTTPS、443 端口与校园域判断落地，并同时接受门户首页与映射站点。
- **0.5.1 已撤回**：该版本可能根本打不开，无法在应用内自动更新；请直接安装 0.5.2。

## 变更

- Agent 与本机 MCP 的校园工具按领域合并为 14 个：只读查询用 `action` 参数选择具体能力，三个写工具保持独立。旧工具名通过 `tools/call` 仍然可用，已保存的工具禁用设置会自动迁移。
- 前端工具调用行按“工具名 + action”显示具体查询名称。

## 验证

- 自动测试：Rust 123 项通过（10 项默认忽略）、前端 29 项通过，Clippy（`-D warnings`）与格式检查通过。
- 构建与产物：发布工作流三平台成功。新增 macOS 启动冒烟检查，在 arm64 与 x64 任务中均启动真实 release 包并确认存活 10 秒。
- 独立复核：arm64 与 x64 更新包签名均有效，`Info.plist` 版本为 0.5.2；arm64 原生启动、x64 在 Rosetta 下启动都存活 10 秒；两个 DMG 的校验和与包内签名通过；全部资产 sha256 与 GitHub 摘要一致，从镜像重新下载后也一致。
- 尚未验证：Windows 只确认构建成功，没有真机启动验证；没有用真实 0.4.0 客户端走完整的检查更新、下载、安装与重启链路。

## 已知限制

- macOS 包仍是 ad-hoc 签名，没有 Developer ID 与公证，首次打开可能提示“无法验证开发者”，需要右键 →「打开」，或到“系统设置 → 隐私与安全性”点「仍要打开」。
- Windows 安装包仍未做 Authenticode 签名，SmartScreen 可能提示“未知发布者”。
- 更新镜像仍临时使用 HTTP 直连 IP（P0），安装包由 minisign 校验；拿到域名与证书后必须切回 HTTPS。
- 0.5.1 用户无法自动升级，必须手动下载 0.5.2 覆盖安装。
- 合并后的校园工具没有在真实 App 中逐项重新调用，MCP 工具截图仍是旧工具面。
