# 校园功能与 Agent 接续（2026-10-19）

## 产品安排与设计状态

沿用现有插件市场承载校园功能，不额外增加平级市场入口。校园功能以独立插件提供页面及可复用业务接口；之后 Agent 工具使用同一业务接口。跨页面的数据归属使用账号 ID 与会话代次。

四张设计稿位于 `design/campus-agent-v1/`。用户已回答“需要调整，我会说明”；它们尚未获批，未实现新前端页面。绘图脚本只是独立设计资料，不是应用页面。后续插件市场 `plugin-market-v2` 已独立获准并实现；此处 Agent 与评教页面仍需调整、确认后再落地。

## 当前后端接口

2026-10-23 补充：考勤流水与课程考勤查询已接入 `school_query`（`attendanceStreams` / `attendanceRecords`），复用账号保存的本科/研究生考勤业务 token，按账号当前直连或 WebVPN 模式访问。校园卡查询（`card` / `cardTransactions`）用已保存的 CAS Cookie 向 ncard 换临时令牌，支持余额与流水。两者页面尚未实现，未实机验收。

2026-10-23 补充：账号现在可以同时保存两套会话。教务、考勤继续使用登录时保存的直连/WebVPN 会话；校园卡、体测等只接受直连的服务改用账号内新增的 `directCookies`（`auth.json`，旧账号缺省为空）。外部网络下首次打开这些工具（或点击侧边栏宠物触发自检）时，Rust 用已保存密码从校园卡登录地址发起一次 CAS 服务登录，成功后保存这套直连 Cookie；需要验证码或手机验证的账号无法自动完成，仍显示“VPN 下不可用”并可手动登录。直连查询遇到失效会续期一次再重试。

2026-10-23（0.3.3 开发中）：`auth.json` 的账号增加按服务保存的 `sites`（旧文件缺省为空），目前用于 `profile`（hello JWT）、`lms`、`library`、`venue`。对应新增 `refresh_profile_session`、`refresh_lms_session`、`refresh_library_session`、`refresh_venue_session` 四个命令，均由已保存密码自动登录；需要验证码、手机验证或未保存密码时返回错误。图书馆和场馆只接受校园网直连，WebVPN 模式下直接提示不可用。传输层新增了**仅限三个固定 HTTP 来源**的放行：`http://rg.lib.xjtu.edu.cn:8086`、`http://202.117.17.144:8080`，以及学籍服务的 `http://hello.xjtu.edu.cn`（OAuth 中转与学籍 API；学籍接口先走 HTTP，失败再试 HTTPS，与校园系统当前行为一致）；三者都只允许直连，其余 HTTP 地址仍被拒绝。hello 的 token 仍只从重定向地址取出，不保存落地页。

2026-10-23 补充：思源学堂的 CAS 登录先跳到 `identity1.xjtu.edu.cn` 的 Keycloak broker，再回到 `login.xjtu.edu.cn` 提交密码，最后经 broker 回到 LMS 建自己的会话。传输白名单因此新增该 HTTPS 主机（仅中转跳转，不接收凭据）；此前登录在重定向阶段被拒，页面显示“校园跳转地址不受支持”。已用本机真实账号完成只读登录与课程 / 活动查询；随后补齐活动详情、附件打开 / 下载与录播回放地址（见下条）。

2026-10-23 思源学堂内部页面：课程列表按学期分组，进入课程后顶部用分段标签在功能分类间切换（作业、学习资料、课程回放、在线视频、直播课堂、讨论、问卷、其他），每类带数量；活动详情显示时间、提交 / 成绩概况、说明文本与附件。附件先请求 `/api/uploads/{id}/blob`，302 到 `media.xjtu.edu.cn`；只接受该 HTTPS 主机的跳转，“打开”用校园窗口查看，“下载”经另存为对话框流式写入，上限 2 GB。录播活动调用 `/api/lessons/{id}/player-url?from_page=course` 取得 RMS 播放地址，用校园窗口打开。实测详情、回放地址与 47 MB 附件下载正常；作业提交、讨论 / 问卷正文与播放器内嵌仍未实现。

`src-tauri/src/school/` 编译入 Rust，主窗口可调用：

- `school_catalog`：校园能力清单及后端进度，现已接入插件市场校园列表，尚无新业务页面的项目显示待接入；`pending` 项不是可用功能。
- `school_query`：查询请求使用封闭的 `Query` 枚举，不接受任意 URL。支持成绩、考试、学期、评教列表、教室选项、空闲教室、全校课程、校历、考勤、校园卡、体测，以及新增的学籍档案、LMS 课程 / 分类活动 / 活动详情 / 作业提交记录、图书馆楼层 / 区域 / 座位、场馆清单 / 时段 / 订单、公开校园通知（栏目列表与按栏目读取）。场馆预订、图书馆预约等写操作尚未开放。
- `lms_open_file` / `lms_save_file`：按附件编号解析 `/api/uploads/{id}/blob` 的 302 目标，只接受 `https://media.xjtu.edu.cn`；前者用校园窗口打开，后者流式写入用户选择的位置，上限 2 GB。
- `refresh_direct_session`：为只接受直连的服务重建 CAS 会话，保存到账号的 `directCookies`；验证码、手机验证或未保存密码会返回错误，由界面提示。
- `school_prepare_evaluations`：按当前账号重新读取开放问卷及真实选项，生成精确的待提交答案。模板等级 1–5 对应选项顺序；文字意见由用户提供，必填文字题为空时返回错误。支持逐题覆盖答案，也支持按问卷编号覆盖评语（只改某位老师的自由文本题，其余沿用默认评语）。预览不会发送评价。
- `school_submit_evaluations`：消费一次性预览 ID 后逐份提交；账号、会话代次与 15 分钟有效期必须匹配。返回每份 `submitted/failed/skipped/cancelled/unknown` 结果，并发送 `school-evaluation-progress` 事件。网络结果不明时不自动重发，停止余下提交，提示刷新学校状态。
- `school_cancel_evaluations`：丢弃尚未执行的预览，或在当前请求返回后停止后续提交。已经发送的请求不会宣称撤回成功。

预览仅保存在本次进程内。重启需要重新查询并预览。查询开始时固定账号快照，返回时检查会话代次，防止切换账号后混入数据。提交期间串行化账号切换；取消通道独立。已确认的提交结果不会因本地会话保存失败而变成可重试失败。

教务连接复用 `auth.json` 的 Cookie，按当前账号直连/WebVPN 模式进入教务首页并验证用户接口。新增白名单仅为 `jwxt.xjtu.edu.cn` 与 `dean.xjtu.edu.cn`。这批尚未把 CAS 登录状态机扩展成所有站点的自动密码重认证；TGC 或教务登录态失效会明确报错。不可宣称跨所有网站免登。
