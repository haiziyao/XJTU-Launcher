## 当前建议与待验证边界

1. **自动访问路径有现成依据。** 参考实现探测考勤入口，缓存结果五分钟，失败后走 WebVPN；并允许站点声明校外是否需要 VPN。我们的添加账号按用户要求默认自动判断。探测应结合目标服务及预期响应，不能仅凭学校主页可打开就认为所有校园系统可访问。
2. **WebVPN 是两步认证。** `ensure_webvpn_login` 使用普通 CAS 流程登录 VPN 本身；`NewWebVPNLogin` 随后把校园系统请求映射至 VPN 地址。Rust 实现不能只改一个 URL 就认为整个登录完成。
3. **多账号需要会话隔离。** 参考项目每账号独立会话管理，同账号又按直连和 WebVPN 区分后端；这一结构适合启动器承载多个校园插件。切换账号或删除账号后，滞后请求不能更新另一账号的界面或缓存。
4. **自有表单必须承接完整状态。** 密码提交后可能需要图片验证码、MFA 或身份选择，不能只实现账号密码输入和一次 POST。账户设置与登录表单的视觉方案仍需用户确认。
5. **存储策略独立设计。** 参考项目支持多种账号存储方式，账号对象包含密码，部分保存路径可写普通文件。本项目继续遵守敏感凭据使用操作系统安全存储的约定；是否记住密码仍需确定，不因参考代码支持就默认保存。
