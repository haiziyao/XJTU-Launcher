# 需求时间线

更新于 2026-11-10。本文件只记录**还没做完的需求**和**已完成的关键节点**，按状态与优先级排列，不绑定版本号；排期确定后再在标题后标注版本。

状态定义：

- **现在做**：已确定优先级、有明确依赖，接下来就处理。
- **下一步**：方向已定，等当前任务腾出人手或依赖解除。
- **待用户验收**：代码已实现，等用户实际使用确认；未验收前不能对外宣称可用。
- **已妥协**：需求本身没有解决，只是接受了降级方案；**不等于完成**，条件变化时重新评估。
- **未来 / 未排期**：在范围内但未定优先级，或依赖外部条件。
- **已完成**：已有实现并记录日期；验收状态单独说明。

新增需求先写进「未来 / 未排期」，确定优先级后再上移；完成一项移到「已完成」并注明版本与日期。实现状态同步到 [DEVELOPMENT.md](DEVELOPMENT.md)。

- [ ] **官网 xjtu-launcher.cn 与 OSS 下载**
  - 现状（2026-11-08）：官网已部署到服务器（`http://8.152.100.169/site/` 可预览），nginx vhost 与限流 zone 已装好；备案期间阿里云不允许解析，域名访问返回 403 `Non-compliance ICP Filing`，暂用 IP。私有 OSS Bucket、两个最小权限 RAM 用户、下载网关与限流均已就绪，v0.5.2 资产已真实上传，`downloads.json` 与更新源都已走 `/download/` 与 `/latest.json` 网关地址；GitHub 变量与 Secrets 已配置，自动上传等待下一版发版验证。2026-11-08 首页与 Q&amp;A 导航新增「社区广场」（`/community/`），页面按应用图标做出三条竖杠与 XJTU 字标，目前只有建设中说明，尚未对接应用内社区内容。
  - 阻塞：`xjtu-launcher.cn` 需要单独 ICP 备案（阿里云「新增网站」），备案通过前域名 80/443 都不能对外服务，也拿不到 Let's Encrypt 证书。
  - 方案：官网只放 HTML、截图与 `downloads.json`；安装包放阿里云 OSS 的**私有** Bucket `xjtu-launcher`，由服务器签发 60 秒链接，不让 Bucket 公共读；每人配额按浏览器 Cookie 算（默认 20 次/10 分钟），nginx 按 IP 的 120 次/分钟、50 并发只做宽松兜底（校园 NAT 下很多人共用一个出口 IP）；`latest.json` 不按 IP 限流；发版时由 `release.yml` 自动上传。
  - 验收：`https://xjtu-launcher.cn` 可访问且证书有效；三个安装包从 `/download/...` 下载完整，SHA256 与 `downloads.json` 一致；直连 OSS 未签名对象返回 403；连续请求出现 429；旧 HTTP 更新镜像在迁移完成前保持可用。
  - 详见 [WEBSITE.md](WEBSITE.md)。

## 已妥协

- [ ] **插件代码运行时（Rust 静态编译的扩展边界）—— 2026-10-29 妥协，未解决**
  - 原目标：让插件能超出“打开链接”的能力，同时不把任意代码直接放进主进程。
  - 原候选：WASM 运行时（wasmtime / wasmi）、本地 sidecar 子进程。
  - **本轮决定（2026-10-29）**：不引入通用运行时。插件全部由项目自己实现，随 App 版本发布。理由：两条候选路线都需要额外定义宿主能力、权限授权、签名分发与双平台验收，复杂度超出当前可接受范围。
  - **没有解决的部分**：第三方仍不能自行扩展插件；插件新能力依赖发版；没有权限沙箱，也没有独立于 App 的插件更新通道。因此本项不能标记为完成。
  - 重新评估条件：出现必须由第三方扩展、或必须独立于 App 更新的真实需求时，再单独做设计评审。
  - 仍然有效的约束：插件只有启用开关，侧栏入口跟随启用状态；不得获得主窗口 IPC 权限；不得读取或上传校园凭据；macOS 公证 / Windows 签名与 GPL 复用检查照旧。2026-11-08 起远端下载与安装也一并移除，插件清单只允许内置 id。

  - 对象：[XJTU-PPT-Capture-Extension](https://github.com/MeowSaint/XJTU-PPT-Capture-Extension)，MIT，v2.5.2，纯 JS 的 Chrome MV3 扩展。
  - 结论：可以集成，但不建议原样嵌入。扩展的核心（跳转采样、翻页检测、去重、框选、IndexedDB、PDF / 图片包导出）是普通 JS，可移植；Chrome 专有部分（permissions / tabs / webRequest / declarativeNetRequest / getDisplayMedia）在 Tauri 没有等价物。
  - 合适路径：先用 SPEC LMS-12 的后端链路取 `review-class` 预签名 `download_url`（已实测，无需 Cookie、支持 Range），再移植截取核心，不移植网络发现与权限逻辑。
  - 体积：源码 1.3 MB（含 `.git`），发布 zip 240 KB；不含 HLS 时前端资源约 200 KB，含 `hls.min.js` 约 730 KB；无原生依赖。截取结果是用户文件，一门课约 30–100 MB，应落在可见的 `xjtu-launcher-file` 下并可由用户清理。
  - 验证结果（2026-11-05，真实账号 + WKWebView）：
    - `player-url` 的 token → `GET https://rms-v5.xjtu.edu.cn/api/v1/auth/embed-token?token=…` 取 bearer → `GET /api/embed/lesson-activities/captures/{replay_code}?lesson_activity_id=…` 返回按课不同的 1–2 路视频；2026-11-05 实测这一课只有 1 路 INSTRUCTOR（959,865,065 字节）。
    - `download_url` 是 `review-class.xjtu.edu.cn` 预签名地址，Range 返回 206，`access-control-allow-origin: *`；响应没有 `content-type`，`content-disposition` 是 attachment。
    - WKWebView 里必须用 `<source type="video/mp4">` 显式声明类型，直接给 `<video src>` 会报 `MEDIA_ERR_SRC_NOT_SUPPORTED`；声明后能解码 1280×720、跳到 600 秒，canvas `drawImage` + `toDataURL` 成功，像素有内容且没有跨域污染。
    - 结论：macOS 端可行；需要给 CSP 增加 `media-src https://review-class.xjtu.edu.cn`。Windows/WebView2 未测试。
  - 探测代码：`src-tauri/src/school/lms.rs` 的 `replay_videos`（`#[cfg(test)]`）与 `live_replay_video_probe`，只读且不输出令牌或地址；`live_todos_probe` 用于上面的待办对比。
  - 风险：预签名地址过期与 2 GB 上限（已验证的视频已接近上限）；两个视频合计超过 2 GB 时不能整段下载；实时共享画面依赖 getDisplayMedia，可能不可用。
