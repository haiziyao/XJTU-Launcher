# 需求时间线

更新于 2026-10-31。本文件只记录**还没做完的需求**和**已完成的关键节点**，按状态与优先级排列，不绑定版本号；排期确定后再在标题后标注版本。

状态定义：

- **现在做**：已确定优先级、有明确依赖，接下来就处理。
- **下一步**：方向已定，等当前任务腾出人手或依赖解除。
- **待用户验收**：代码已实现，等用户实际使用确认；未验收前不能对外宣称可用。
- **已妥协**：需求本身没有解决，只是接受了降级方案；**不等于完成**，条件变化时重新评估。
- **未来 / 未排期**：在范围内但未定优先级，或依赖外部条件。
- **已完成**：已有实现并记录日期；验收状态单独说明。

新增需求先写进「未来 / 未排期」，确定优先级后再上移；完成一项移到「已完成」并注明版本与日期。实现状态同步到 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 已妥协

- [ ] **插件代码运行时（Rust 静态编译的扩展边界）—— 2026-10-29 妥协，未解决**
  - 原目标：让插件能超出“打开链接”的能力，同时不把任意代码直接放进主进程。
  - 原候选：WASM 运行时（wasmtime / wasmi）、本地 sidecar 子进程。
  - **本轮决定（2026-10-29）**：不引入通用运行时。插件全部由项目自己实现，随 App 版本发布。理由：两条候选路线都需要额外定义宿主能力、权限授权、签名分发与双平台验收，复杂度超出当前可接受范围。
  - **没有解决的部分**：第三方仍不能自行扩展插件；插件新能力依赖发版；没有权限沙箱，也没有独立于 App 的插件更新通道。因此本项不能标记为完成。
  - 重新评估条件：出现必须由第三方扩展、或必须独立于 App 更新的真实需求时，再单独做设计评审。
  - 仍然有效的约束：插件只有启用开关，侧栏入口跟随启用状态；不得获得主窗口 IPC 权限；不得读取或上传校园凭据；包版本、摘要、来源与更新都必须校验；macOS 公证 / Windows 签名与 GPL 复用检查照旧。

## 未来 / 未排期

- [ ] **思源学堂信息架构改版（2026-10-31 用户提出，未排期）**
  - 版式：现在整页是一条一条的横栏，单调、没有轻重。要按重要性分层，不是所有内容都同一权重。
  - 学期语义：真机缓存数据显示 `term` 字段全部为空，只有 `year`（2024-2025 / 2025-2026 / 2026-2027）与每门课的 `start` / `end`。当前前端按 `year + term` 分组，`term` 为空时同一年全部并成一条，所以看起来「盲目合并」。
  - 目标：把学年拆成有名称的阶段（如大一上、大一下、大一暑期小学期），从 `start` 日期聚类推断（真实数据里秋季约 9 月、春季约 2 月、夏季约 5–6 月开课），并展示可读的年级标签。
  - 年级标签需要入学年份：学籍档案是否提供该字段待确认；退而求其次只能按最早有课学年推导，推导值必须标明是推导，不能当作事实。
  - 课程选择：有作业 / 待办的课程置顶为可点选的横栏（可新做一种样式）；内容少的课程折叠进「其他课程」二次选择。整体轻重分明。
  - 约束：语义没确认前不动手；不伪造学期或年级数据；视觉改动先参考图并获同意。
- [ ] **插件过多时的选择与发现**
  - 问题：插件全部内置后功能会越来越多；平铺成一张列表会让用户不知道装哪个、开哪个。
  - 方向（待定）：默认精简（核心功能默认启用，其余关闭）；按身份 / 场景推荐（本科 / 研究生、教务 / 生活）；市场内分组与标签；安装前说明用途和影响范围。
