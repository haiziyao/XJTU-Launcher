# 开发文档

本目录是工程内部资料。`main` 上的内容与最新发布版一致；日常开发在 `codex/*` 分支进行，完成后合入 `main`。

## 目录分工

| 目录               | 面向           | 内容                                                                 |
| ------------------ | -------------- | -------------------------------------------------------------------- |
| `docs/`            | 使用者与产品   | 根目录 README 的用户文档、设计稿与评审、版本发布说明、界面截图       |
| `dev-docs/`        | 开发者         | 约定、开发指南、当前状态、需求时间线、发布与签名流程、组件规范、参考研究 |
| `dev-docs/archive/`| 追溯           | 历史讨论、旧版实现记录、旧约定原文；不作为当前规则                   |

判断标准：读者是**使用者或产品决策者**就放 `docs/`；读者是**写代码、发布或验收的人**就放 `dev-docs/`。两边都需要的结论（如"当前版本能做什么"）在 `docs/` 面向用户表述，在 `dev-docs/` 记录实现与验收边界。

## 从这里开始

1. [约定手册](CONVENTIONS.md)：**唯一规则来源**。设计授权、数据安全、分支发布、验收标准都在这里。
2. [开发指南](DEVELOPMENT.md)：代码结构、启动方式、检查命令、当前实现与接续任务。
3. [需求时间线](need-do.md)：按状态与优先级排列的待做需求、依赖和验收条件。
4. [P0 待办](P0.md)：正式发布前必须补齐的安全与可用性缺口。
5. [根目录 AGENTS.md](../AGENTS.md)：给 coding agent 的硬约束摘要。

## 更新规则

- 规则变化先改 [CONVENTIONS.md](CONVENTIONS.md)，再同步 `AGENTS.md` 的硬约束摘要；不要在两处各写一份完整规则。
- 需求增删改先改 [need-do.md](need-do.md)；完成的条目移到「已完成」并注明版本与日期。
- 实现状态变化同步 [DEVELOPMENT.md](DEVELOPMENT.md) 的「当前可用与未完成项」。
- 移动或重命名本文档时，同步更新根目录 README、`AGENTS.md` 和所有交叉链接。
